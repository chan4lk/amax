# Time demo: changes 070 to 073, end to end

A hands-on walkthrough of everything the four Time changes added, on your local `amax` database with fictional Lumen Labs
data. Work through the parts in order: each part leaves the data the next one expects. Allow about 90 minutes.

| Change | What it added | Part |
|---|---|---|
| 070 Time entry corrections | Fix and remove hours through chat, locked approved weeks, change requests, page-aware chat, bulk remind and approve, one session per browser | C |
| 071 Time access and integrity | Entity scope for Admins, time settings (allocated projects only, back-dating, future dates), duplicate warnings | B |
| 072 Time consumers sync | Finance and Reports follow week status, the right approvers are notified, weekly targets and utilisation (email: tests) | D |
| 073 Time workflow enhancements | Weekend hours, day reminders, the daily schedule, ThisWeek capacity, approval checks, and the Team grid (amendment 1) | A, E |

Everything here is a demo: names, clients and figures are fictional. Some behaviour can only be checked by the
automated tests; see "Covered by tests only" at the end.

## 0. Set up

### Prerequisites

- Docker (or Podman) with the dev Postgres container from `deploy/dev/compose.yaml` (`amax-dev-postgres`, port 5440).
- `apps\web\.env.local` with `DATABASE_URL` (the app role on the local database), `AUTH_SECRET`, `AUDIT_HASH_KEY`,
  `CRON_SECRET`, `AMAX_AUTH_DEMO=1`, `AMAX_AUTH_DEMO_TENANT` and `AMAX_AUTH_PASSWORD_TENANT` (both
  `11111111-1111-4111-8111-111111111111`), and `ANTHROPIC_API_KEY` so chat uses the real model. See the README's
  "Run locally".

### Start the app

From the repo root, in PowerShell:

```powershell
docker start amax-dev-postgres
pnpm install --frozen-lockfile
$env:DATABASE_MIGRATE_URL = "postgres://amax:amax@127.0.0.1:5440/amax"
pnpm db:migrate
pnpm --filter @amax/web build      # optional: catches type and build errors
pnpm --filter @amax/web dev
```

On its first start against a database, `dev` loads the demo data (every module's Lumen Labs data, then this
walkthrough's week 43) and prints `demo data: seeded …`. Later starts print `demo data: already loaded` and change
nothing, so whatever you did in the demo stays. Check you have the walkthrough data: Team time for week 43 shows
**125.0 h** for Maya.

The first page load can reload itself for a minute while Turbopack compiles. If it never settles, stop the server,
delete `apps\web\.next\dev`, and start it again. This happens after a production build (`next build`) has used `.next`.

### Signing in

Open <http://localhost:3000/signin> and type the person's email in **Demo user (fixtures only)**, then **Sign in as
demo user**. To switch person, use **Sign out to switch account** on `/signin`. Or use a second browser profile or a
private window, so two people can be signed in side by side.

### The jobs tick

Bells, email, Finance and Reports update from events, which the jobs tick delivers. `dev` runs it on its own every
10 seconds and prints a line when it delivers something (`jobs tick: 3 events`). When a step says **tick**, wait about
10 seconds and reload. Finance takes **two** ticks, so **tick twice** means about 20 seconds: the first recalculates
the draft, the second refreshes its **Accept draft** suggestion.

### How chat writes

Pages have no edit forms. Every change goes through chat:
- **Ask amax:** opens chat. A row's or card's **+** pins that record to the chat.
- **The card:** chat proposes the write as a card. Check its figure and lines, then press its button, which names the
  action (**Log 2 h**, **Approve**, **Send back**, **Send request**, **Apply change**; red for a removal). The steps
  below call it **Add it**. **Edit** changes something; **Cancel** drops it. Nothing changes until you press the button.
- **After confirming:** the card folds to one line that says what happened, such as "✓ Logged 2 h · Fleet Tracker,
  Sat Oct 24".

The model's wording varies, so the expected results below quote the cards and screens, not the replies.

## Covered by tests only

These can't be shown from the screen in a local demo; the automated tests cover them (`pnpm test` with
`DATABASE_MIGRATE_URL` set):

- **070:**
  - undoing a commit-draft suggestion removes its entry from Reports;
  - an Admin can't reopen their own week;
  - writes that name a week by person need an explicit week.
- **071:**
  - Payroll's overtime reads approved hours through `time:totals` (no Payroll user in the demo);
  - a commit pushed twice, or on two branches, is logged once;
  - `log_time` with a `clientRef` is idempotent.
- **072:**
  - email for approved, sent-back and reopened weeks (sent through Microsoft Graph, which isn't configured locally; the tests use a fake wire);
  - every event delivered twice gives the same Finance figures;
  - an invoiced period isn't rewritten.
- **073:**
  - weekend commit suggestions (they need a GitHub push);
  - the weekly reminder in two time zones;
  - 100 people on Team time load in under 2 seconds.

## Start again

The demo loads once per database, so to start over, recreate the database and start `dev` again. **This deletes
everything in your local `amax` database.** Stop the dev server first, then:

```powershell
docker exec amax-dev-postgres psql -U amax -d postgres -c "drop database if exists amax with (force)" -c "create database amax"
$env:DATABASE_MIGRATE_URL = "postgres://amax:amax@127.0.0.1:5440/amax"
pnpm db:migrate
pnpm --filter @amax/web dev
```
