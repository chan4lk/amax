- [minor B6] `modules/git-accounts/server/read.ts:33` `/^[0-9a-f-]{36}$/i` lets through strings that are not UUIDs, such as 36 dashes. Postgres then throws 'invalid input syntax for type uuid' when it compares against `connect_state.id`, so the screen errors instead of showing the fixed unknown-return sentence. Fix: validate with a strict UUID pattern (or `z.uuid()`) and return null when it fails. (round 3) <!-- fp:a5936c26615b class:other -->
- [minor B12] `modules/git-accounts/server/connect.ts:84` `recordReturn` is a `defineService` write, so every call writes an audit row with `after: { result }`. That includes calls that change nothing: a duplicate return where the claim is held elsewhere, a state that is someone else's or unknown, or `stored_at` already set. The audit trail then shows results being recorded that were never stored. Return a flag for whether a row was updated, and only report the result in `after` when it was, or skip the write path entirely when the update matched no row. (round 5) <!-- fp:a1bc61c2a533 class:other -->
