# Follow-ups

Deferred by the review loop: minors and pre-existing findings.

- [minor B11] `modules/delivery/module.ts:122` The new `delivery.release-off-track` rule has no `except`, and `ReleaseStatusChanged` carries no `by`. When the PM's own edit moves the release to overdue (`update_release` with a target in the past, or `create_release` with one), the PM gets an urgent notice about their own action. The other Delivery owner rules leave out the person who acted (`except: "by"`). Fix: add `by` to the payload for create and update sources (null for schedule) and set `except: "by"`. (round 1) <!-- fp:f6eee8e28121 class:other -->
- [minor B4] `modules/delivery/server/release-tracking.ts:103` The rule for which environment serves a category is written twice. `categoryEnv` decides it in SQL (`lower(name) = category`, or `is_prod`). `serves()` decides it again in JS (`String(e.name).toLowerCase() === c`, or `e.is_prod`). The strand guard in `strandsReleases` uses the JS copy, and completion and `categoryProblem` use the SQL copy, so a change to one (trimming, aliases such as 'Staging' for UAT) can let them disagree. Fix: derive `serves` from the same matcher, or check the guard through `categoryEnv` after the change. (round 5) <!-- fp:d77f4f66c847 class:other -->
- [minor B4] `modules/delivery/server/release-list.ts:3` `STATUS_FILTERS` writes the status labels again ('In progress', 'Off track', 'Completed', 'Planned', 'Untracked'), separately from `STATUS_LABEL` and `statusLabel` in `release-status.ts`. Renaming a status label in one place leaves the filter tab and the chip saying different things. Fix: build the tab labels from `statusLabel`. (round 5) <!-- fp:984bc14d26fe class:other -->
- [minor B1] `modules/delivery/server/services.ts:521` When `update_release` tracks a release, or moves it to a category it already reached, the completion is written with source 'deployment'. The status history then reads 'Deployed to UAT' at the time of the edit, and gives the edit's author as the actor. An environment change got its own source in 0028 ('environment'), but this edit-driven completion did not. Fix: record it as 'update' with the deployment id, and let `why()` say e.g. 'Edited; already in UAT'. (round 5) <!-- fp:a0443f5fc7da class:other -->
