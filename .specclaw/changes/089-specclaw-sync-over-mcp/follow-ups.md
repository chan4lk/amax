## Open at the five-pass cap (round 5, final, 2026-11-09)

The review loop stopped here (AGENTS.md: five passes at most). Neither is a blocker. Both are for a follow-up change.

- **[major B1] `modules/delivery/server/push.ts:98`** A branch whose own folder reuses a number that `main` already
  synced under another folder isn't caught: the branch tree holds only its own folder, so `duplicateNumbers` sees one
  dir, and the push overwrites the stored proposal (key matches, commit newer). Since 089, CI pushes every
  `specclaw/*` branch after each merge, so this can happen before the PR's number check stops the PR. Fix: when the
  stored row's `source_ref` (its folder name) isn't `r.dir`, treat the record as a duplicate: skip it with "two changes
  numbered NNN" and set needsReview. Same in the self-sync. Add a table test.
- **[major B6] `modules/delivery/sync/bin.ts:35`** The self-sync's withdrawal now depends on `refOf()` stripping
  `@<sha>`, which only strips 7–40 hex characters, and `--sha` isn't checked. A short or non-hex sha leaves it in the
  ref, so stored and read refs never match and gone folders are silently kept (no hold line). Fix: refuse a `--sha`
  that isn't `/^[0-9a-f]{7,40}$/i`, as `PushInput` does, or resolve it with `git rev-parse`.
